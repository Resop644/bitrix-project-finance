# Bitrix24 Project Finance

Веб-приложение для ручного учета доходов и расходов по проектам с интеграцией Bitrix24.

## Что умеет

- доходы и расходы по проектам;
- прибыль и рентабельность;
- стандартные статьи: внешние программисты, внутренние программисты, расходы на ИИ, аренда сервера, дивиденды;
- пользовательские статьи доходов и расходов;
- сотрудники и роли проекта;
- авторизация сотрудников;
- Bitrix24 OAuth 2.0 и серверное хранение refresh/access token;
- определение текущего пользователя Bitrix24 через `user.current`;
- получение проектов/групп Bitrix24 через `sonet_group.get`;
- получение пользователей Bitrix24 через `user.get`;
- синхронизация Bitrix24-групп с локальными проектами;
- нативно-ориентированный интерфейс для Bitrix24 iframe;
- устойчивое сопоставление через `bitrix_group_id`;
- детальный тест-план и контрольный demo-сценарий.

## Быстрый запуск за 5 минут

Требуется Node.js 20+.

```bash
cp .env.example .env
npm install
npm test
npm run demo
npm start
```

Откройте `http://localhost:3000`.

Demo-сценарий создаёт проект **«Демонстрационный проект»**:

| Показатель | Значение |
|---|---:|
| Доход | 1 000 000 ₽ |
| Расходы | 500 000 ₽ |
| Прибыль | 500 000 ₽ |
| Рентабельность | 50,0% |

`npm run demo` проверяет итоговые значения и не дублирует операции при повторном запуске.

### Переменные окружения

Скопируйте `.env.example` в `.env`. Для production обязательно задайте собственные `ADMIN_PASSWORD`, `BITRIX_CLIENT_ID`, `BITRIX_CLIENT_SECRET` и длинный случайный `BITRIX_ENCRYPTION_KEY`.

## Проверка качества

`npm test` проверяет формулы прибыли и рентабельности, включая отрицательную прибыль, нулевой доход и контрольный сценарий 1 000 000 / 500 000.

Полный сценарий ручной приемки находится в [`docs/TEST-PLAN.md`](docs/TEST-PLAN.md) и включает CRUD, права доступа, пользовательские статьи, команду проекта, Bitrix24 bootstrap, синхронизацию и OAuth refresh.

## Подключение Bitrix24

1. Разверните приложение на HTTPS-домене, доступном из Bitrix24.
2. Создайте локальное/внешнее приложение Bitrix24.
3. Укажите URL обработчика `https://YOUR-DOMAIN/bitrix`.
4. В разрешениях приложения включите минимум `user_basic`, `user` и `sonet_group`.
5. На сервере задайте `BITRIX_CLIENT_ID` и `BITRIX_CLIENT_SECRET`.
6. Откройте приложение внутри Bitrix24. `BX24.init()` и `BX24.getAuth()` передают авторизационные данные на `/api/bitrix/bootstrap`.
7. Сервер определяет пользователя через `user.current`, создаёт локальную сессию и хранит OAuth credentials зашифрованными.
8. При истечении access token сервер использует refresh token и повторяет запрос к Bitrix24.
9. Кнопка **«Синхронизировать проекты»** загружает активные Bitrix24-группы и сопоставляет их с локальными проектами.

`bitrix24/app.json` содержит шаблон конфигурации. Перед установкой замените `YOUR-DOMAIN` на реальный HTTPS-домен.

**Важно:** реальные секреты и токены не должны попадать в Git. В репозитории используются только шаблонные значения.

## API Bitrix24

- `POST /bitrix/install` — прием install/auth payload;
- `POST /api/bitrix/bootstrap` — создание локальной сессии из Bitrix24 auth;
- `GET /api/bitrix/context` — статус подключения;
- `GET /api/bitrix/groups` — группы/проекты Bitrix24;
- `GET /api/bitrix/users` — пользователи Bitrix24;
- `POST /api/bitrix/sync-projects` — синхронизация групп в локальные проекты.

## Архитектура и безопасность

Backend: Node.js + Express + SQLite. Frontend: HTML/CSS/JS без обязательного build pipeline.

- SQL-запросы параметризованы;
- пароли хешируются через Node.js `crypto.scrypt`;
- Bitrix access/refresh token хранятся в AES-256-GCM зашифрованном виде;
- `BITRIX_CLIENT_SECRET` не передается в браузер;
- доступ к проекту проверяется по роли/участию в проекте;
- удаление проекта доступно только администратору;
- менеджер проекта может изменять проект и участников;
- для high-load production рекомендуется PostgreSQL, HTTPS, reverse proxy и резервное копирование БД.
